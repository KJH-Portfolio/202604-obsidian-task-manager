# 3. MyWorld Task Manager - 플러그인 설계 및 구현 명세서

이 문서는 기존 옵시디언(Obsidian) 보관소 내에 흩어져 있던 CSS 스니펫과 Templater 스크립트를 하나의 독립적인 **TypeScript 기반 옵시디언 플러그인**으로 완결성 있게 이식하기 위한 종합 설계 및 물리적 구현 명세서입니다.

---

## 1. 프로젝트 개요 및 기획 의도

*   **플러그인명**: MyWorld Task Manager (`myworld-task-manager`)
*   **기획 배경 (의존성 제로화)**: 기존 시스템은 `Templater` 스크립트를 사용하므로 사용자가 수동 관리해야 했으나, 이를 플러그인 자체 시스템으로 내재화하여 초기 사용자 경험(UX)을 극대화합니다.
*   **개발 목적**:
    1.  데일리 스케줄 노트와 프로젝트 개별 파일 간의 정밀한 **양방향 할 일(Task) 동기화** 구현.
    2.  📅 날짜 라벨을 분석하여 **디데이 우선순위 마커 자동 계산 및 트리형 정렬** 처리.
    3.  하루 마감 시 **루틴 버튼 리셋, 월간 통계 테이블 누적, 주간/월간 통계 그래프 아카이빙** 자동화.
    4.  노트 양식(Template) 내장 및 원클릭 생성을 통한 셋업 마법사 지원.

---

## 2. 핵심 기능 요구사항 명세 (Functional Requirements)

### [기능 A] 양방향 할 일 동기화 (Task Sync)
*   **동작**: 스케줄 노트 내 `# Project` 섹션의 링크를 스캔하여 대상 프로젝트 파일을 식별합니다. 스케줄 노트에서 수정한 상태(`[x]`)와 텍스트를 프로젝트 파일의 `# 실행` 구역 블록 ID(`^id`)에 정확히 덮어씁니다. 완료된 항목은 스케줄에서 소거하고 프로젝트의 `# 계획` 구역으로 넘깁니다.
*   **완전 소거 (`//`)**: 텍스트 끝에 `//`를 붙이고 동기화 시 양쪽 문서에서 라인 자체를 완벽하게 삭제(Splice)합니다.

### [기능 B] 디데이 계산 및 자동 정렬 (D-Day & Sorting)
*   **동작**: 📅 날짜 라벨을 읽어 `#Past`, `#D-0`, `#D-1` 등의 디데이 마커를 자동 갱신합니다. 부모의 마커를 자식에게 하향 전파하며, **긴급도 순위 -> 마감 날짜 순**으로 문맥(주석 등)을 보존한 채로 자동 정렬합니다.

### [기능 C] 하루 일과 리셋 및 통계 아카이빙 (Daily Reset & Archive)
*   **동작**: 리셋 명령어 실행 시 회고 입력창을 팝업하고, 체크된 루틴을 이모지(🟦🟩🟨🟥)로 변환해 월간 표에 이관합니다.
*   **데이터 무결성 방어**: 동적 헤더 매핑으로 템플릿 칸 이름이 달라도 매칭하며, 에러 발생 시 2-Phase Commit 롤백으로 파일 파괴를 방지합니다. 주간 통계 생성 시 표의 뼈대를 동적으로 생성해 깨짐을 차단합니다.

### [기능 D] 빠른 할 일 캡처 (Quick Capture)
*   **동작**: ✏️ 버튼 클릭 시 옵시디언 전용 입력 모달이 팝업되며, 입력된 내용을 메인 스케줄 문서의 `# Todo` 아래에 즉시 주입하고 자동 정렬 로직을 엽니다.

### [기능 E] 템플릿 및 시스템 셋업 헬퍼 (Setup Wizard)
*   **동작**: 설정 화면에서 클릭 시 PARA(Inbox, Project 등) 구조와 제텔카스텐 지식 관리 폴더 구조를 자동 생성합니다. 스케줄 파일과 프로젝트 템플릿 양식도 지정된 경로에 즉각 생성해 줍니다. 동적 경로 팝업 모달을 지원합니다.

### [기능 F] 스타일 내장 (CSS Build-in)
*   **동작**: 루틴 칩 버튼(`inline-routine.css`)과 디데이 컬러 마커(`fix-task-indent.css`) 스타일을 플러그인에 내장하여 추가 스니펫 설치 없이 렌더링되게 합니다.

  - inline-routine

## 4. 시스템 아키텍처 및 세부 구현 설계

### 물리적 파일 구조
```
myworld-task-manager/
├── src/
│   ├── main.ts            # 플러그인 진입점 (명령어 및 리스너 등록)
│   ├── settings.ts        # 설정 화면 (GUI 설정 필드 구성 및 경로 자동완성)
│   ├── TaskUtils.ts       # 디데이 연산, 트리 정렬, 헬퍼 알고리즘
│   ├── Synchronizer.ts    # 양방향 동기화 처리 및 클린업
│   ├── ResetManager.ts    # 루틴 리셋, 이모지 이관 및 아카이브 대시보드 조립
│   └── TemplateHelper.ts  # 템플릿 생성, PARA/제텔카스텐 셋업 헬퍼
├── styles.css             # 빌트인 디자인 스타일시트
├── manifest.json          # 플러그인 메타데이터 (버전 등)
├── package.json           # 빌드 의존성 및 esbuild 스크립트 정의
└── esbuild.config.mjs     # esbuild 컴파일 설정 (Node 내장모듈 호환)
```

### 세부 모듈별 구현 상세 로직
1.  **`main.ts`**: `Plugin` 클래스 상속. 플러그인 로드 시 명령어 등록 및 스타일시트를 주입합니다. 퀵 캡처 입력 모달(`QuickCaptureModal`)을 호출합니다.
2.  **`settings.ts`**: 사용자 설정 데이터(`settings`)를 로컬 스토리지에 I/O 처리합니다. 동적 경로를 입력받는 팝업 모달(`TemplatePathModal`)을 통해 유연성을 더합니다.
3.  **`TaskUtils.ts`**: 날짜 파싱 및 `//` 완전 삭제 정규식을 통해 블록 단위 태스크 상태 전이를 계산합니다.
4.  **`Synchronizer.ts`**: 블록 ID를 기반으로 각 태스크를 Map에 캐싱한 후 대조하여 변경 사항만 추출(Patch)합니다. 진행도 %를 계산해 HTML 바를 렌더링합니다.
5.  **`ResetManager.ts`**: 동적 헤더 매핑으로 상하단 표 열 길이가 달라도 이름을 매칭시켜 데이터를 누적합니다. 10일 구간 단위 데이터 분리를 위해 정규식으로 마크다운 표를 쪼개어 읽습니다.
6.  **`TemplateHelper.ts`**: `vault.createFolder` 함수를 체인(Chain)으로 연결해 상위 폴더가 없으면 안전하게 차례대로 생성하는 재귀 헬퍼를 포함합니다.

## 5. 플러그인 설정 스키마 및 명령어 목록

```json

  "projectDirectory": "1. Project",

  "templatesDirectory": "3. Resource/01.Templates", 
  "customTemplates": {
    "dailySchedule": "", // 비어있으면 내장 양식 사용
    "projectNote": ""
  }
}
```

### 등록 명령어 (Commands)
| ID | 이름 | 버튼 | 연결 모듈 |
|---|---|---|---|
| `task-manage` | 양방향 프로젝트 동기화 | ⚡️ | Synchronizer |
| `daily-task-reset` | 일간 루틴 리셋 및 기록 | 🌤️ | ResetManager |
| `push-project-to-schedule` | 프로젝트 ➡️ 스케줄 반영 | 📤 | Synchronizer |
| `monthly-stats-archive` | 통계 수동 아카이브 | 🗂️ | ResetManager |
| `quick-capture` | 빠른 할 일 등록 | ✏️ | main.ts |
| `open-memo` | 임시 메모 생성/열기 | 📋 | main.ts |
| `myworld-setup-para` | PARA 폴더 일괄 셋업 | - | TemplateHelper |
| `myworld-setup-zettelkasten` | 제텔카스텐 일괄 셋업 | - | TemplateHelper |
