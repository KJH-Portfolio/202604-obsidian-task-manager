# MyWorld Task Manager - 플러그인 개발 및 공식 등록 가이드북

이 문서는 **MyWorld Task Manager** 플러그인의 로컬 개발 환경 구축 방법부터 로컬 보관소 내 테스트, 그리고 최종적으로 GitHub에 릴리즈하여 옵시디언 커뮤니티 플러그인으로 공식 승인을 받아 배포하는 전체 프로세스를 안내하는 실행 가이드입니다.

---

## 1. 로컬 개발 및 테스트 환경 구축

옵시디언 플러그인은 TypeScript 기반으로 개발되며, 컴파일 과정을 거쳐 하나의 `main.js` 파일로 빌드되어 구동됩니다.

### ① 개발 도구 설치
1.  **Node.js 및 npm 설치**: 개발 컴퓨터에 Node.js가 설치되어 있어야 합니다. (버전 18 이상 권장)
2.  **VS Code 설치**: 코딩과 터미널 제어가 용이한 VS Code 등의 에디터를 준비합니다.

### ② 개발용 뼈대(Boilerplate) 생성 및 패키지 설치
옵시디언 공식 플러그인 템플릿 저장소를 바탕으로 프로젝트 폴더를 구성합니다.
```bash
# 1. 공식 플러그인 샘플 다운로드 및 폴더 생성
npx degit obsidianmd/obsidian-sample-plugin myworld-task-manager

# 2. 프로젝트 폴더로 이동
cd myworld-task-manager

# 3. 개발에 필요한 패키지(obsidian API 등) 자동 설치
npm install
```

### ③ 로컬 테스트 링크 연결 (Symlink 설정)
코드를 수정하고 빌드하면 사용자님의 현재 옵시디언 보관소(`c:\Users\kim50\OneDrive\Desktop\Obsidian`)에서 플러그인이 즉시 새로고침되어 반영되도록 심볼릭 링크(Symlink)를 연결하는 것이 테스트하기 가장 좋습니다.
```powershell
# Windows PowerShell 관리자 권한으로 프로젝트 폴더 내에서 실행
# 개발 폴더와 옵시디언 실제 플러그인 폴더 간의 링크 생성
New-Item -ItemType Junction -Path "c:\Users\kim50\OneDrive\Desktop\Obsidian\.obsidian\plugins\myworld-task-manager" -Value "C:\개발폴더경로\myworld-task-manager"
```
*   이렇게 연결해두면 개발 폴더에서 빌드된 파일이 옵시디언 테스트 보관소 폴더로 자동 매칭됩니다.

### ④ 빌드 실행
개발 폴더 내에서 코드를 작성한 후, 아래 명령어를 실행하여 빌드합니다.
*   **실시간 개발 모드 (추천)**:
    ```bash
    npm run dev
    ```
    *   이 명령어를 켜두면 소스코드를 수정하고 저장할 때마다 자동으로 컴파일이 일어나 `main.js` 파일이 실시간으로 갱신됩니다.
*   **배포용 최종 빌드**:
    ```bash
    npm run build
    ```

## 2. 코드 구현 및 로컬 검증 단계

1.  **코드 모듈 작성**: 기획서에 기재된 6개의 모듈(`main.ts`, `settings.ts`, `TaskUtils.ts` 등) 코드를 `src/` 폴더 내에 작성합니다.
2.  **스타일 시트 이식**: 기존 `fix-task-indent.css`와 `inline-routine.css` 소스코드를 프로젝트 루트의 `styles.css`에 붙여넣습니다.
3.  **메타데이터 수정**: 프로젝트 루트의 `manifest.json`을 수정하여 고유 ID(`myworld-task-manager`), 표시 이름, 개발자 정보 등을 정확히 기입합니다.
4.  **로컬 보관소 테스트**:
    *   옵시디언 설정 ➔ `커뮤니티 플러그인` ➔ `설치된 플러그인` 목록 우측의 **새로고침** 버튼을 누릅니다.
    *   목록에 나타난 `MyWorld Task Manager` 플러그인의 토글 스위치를 활성화합니다.
    *   단축 버튼 및 동기화/리셋 기능이 텍스트 손상 없이 정상 작동하는지 직접 조작하며 검증합니다.

## 3. GitHub 배포본(Release) 발행

옵시디언 공식 마켓플레이스에 배포하려면, 사용자의 코드가 GitHub에 정상적으로 릴리즈되어 있어야 합니다.

### ① 깃허브 저장소 업로드
*   GitHub에 새로운 Public 저장소를 생성합니다.
    *   **MyWorld Task Manager 실제 저장소**: `https://github.com/KJH-Portfolio/202604-obsidian-task-manager`
*   로컬 개발 코드를 저장소에 Push합니다. (단, 무거운 `node_modules` 폴더는 `.gitignore`에 등록하여 제외해야 합니다.)

### ② 배포용 Release 자동화 (GitHub Actions & Attestations) ⭐
**[IMPORTANT 변경 사항]**
과거에는 로컬에서 직접 빌드한 후 `main.js` 등의 파일을 깃허브 Release 페이지에 수동으로 올리는 작업을 해야 했으나, **앞으로 새 버전을 출시하실 때는 무조건 수동 업로드를 하시면 안 됩니다.**

현재는 깃허브 액션 스크립트(`.github/workflows/release.yml`)가 구축되어 있어 빌드와 **보안 서명(Artifact Attestations)**이 100% 자동화되어 있습니다. 다음의 아주 간편한 배포 방식을 사용하세요:

1.  로컬 환경에서 코드 수정 및 버전업(`manifest.json`, `package.json`, `versions.json`)을 마친 후 `Commit & Push` 합니다.
2.  깃허브 터미널(Git) 또는 데스크탑 앱에서 새 버전에 해당하는 **태그(Tag)를 생성하고 Push** 합니다.
    *   터미널 예시: `git tag 1.0.26` ➔ `git push origin 1.0.26`
3.  **🎉 끝입니다!**
    *   태그가 깃허브에 올라가는 즉시 깃허브 액션 서버가 깨어나서, `main.js`와 `styles.css`를 최신 코드로 자동 컴파일합니다.
    *   이후 "이 파일은 해킹되지 않은 안전한 파일이다"라는 암호학적 증명서(Attestations)를 찍어서 자동으로 Release 페이지를 생성하고 에셋을 달아줍니다!
    *   (스캐너 대시보드에서 완벽한 통과 점수를 받으실 수 있습니다.)

> [!WARNING] 봇 캐싱에 의한 재검사 거부 우회 (버전업 트러블슈팅)
> 만약 1.0.0 버전으로 올렸다가 봇에게 심사 거절(Build Failed 등)을 당한 뒤, 코드를 고쳐서 다시 1.0.0 태그로 릴리즈를 덮어씌워도 봇은 "이미 검사한 버전"이라며 **재스캔을 완강히 거부**합니다. 이럴 때는 `manifest.json`과 `package.json` 내부의 `version` 숫자를 `1.0.1`로 명시적으로 올리고(Bump), 깃허브에서도 **새로운 태그(`1.0.1`)**로 릴리즈를 발급해야만 봇을 강제 재작동시킬 수 있습니다.

## 4. 옵시디언 커뮤니티 플러그인 공식 등록 신청 (최신 변경 사항)

과거에는 깃허브 저장소(obsidian-releases)에 직접 Pull Request(PR)를 보내는 방식을 사용했으나, **최근 옵시디언의 등록 절차가 전용 개발자 대시보드(웹사이트)를 이용하는 방식으로 완전히 개편(현대화)되었습니다.**

### ① 공식 개발자 대시보드 로그인 및 연동
1.  **[community.obsidian.md](https://community.obsidian.md)** 주소로 접속합니다.
2.  사용자님의 공식 옵시디언 계정(Obsidian Account)으로 로그인합니다.
3.  개발자 프로필 설정(Profile)으로 들어가서 본인의 **GitHub 계정을 연동(Link)**합니다. (이 과정을 통해 옵시디언이 사용자님이 해당 깃허브 저장소의 주인인지 인증합니다.)

### ② 플러그인 등록 신청 (Submit)
1.  대시보드 좌측 사이드바의 **Plugins** 메뉴를 선택합니다.
2.  **New plugin** (또는 Submit a new plugin) 버튼을 클릭합니다.
3.  미리 배포용 릴리즈(Release) 세팅을 마친 본인의 **GitHub Repository URL**을 입력창에 붙여넣고, 개발자 정책(Developer Policies)에 동의한 후 제출(Submit)을 누릅니다.

### ③ 자동화 검사 및 심사 프로세스
1.  제출이 완료되면 옵시디언 대시보드 시스템이 깃허브 저장소의 릴리즈 파일(main.js, manifest.json 등)과 라이선스, 보안 위반 사항을 1차적으로 스캔합니다.
2.  스캔을 통과하면 옵시디언 관리자 그룹의 **수동 코드 리뷰(Manual Review)** 대기열로 넘어가게 되며, 심사는 보통 수일 내에 완료됩니다.
3.  최종 승인이 완료되면 전 세계 모든 옵시디언 사용자가 앱 내 커뮤니티 탭에서 **MyWorld Task Manager**를 손쉽게 다운로드할 수 있게 됩니다!

## 5. 🚀 향후 업데이트 (버전 업그레이드) 가이드

플러그인 배포 이후, 버그를 수정하거나 새로운 기능을 추가하여 기존 사용자들에게 업데이트를 배포하려면 다음의 절차를 따릅니다.

### ① 버전 숫자 올리기 (Version Bump)
가장 먼저 플러그인의 버전을 올려야 합니다.
1. `manifest.json`을 열고 `"version": "1.0.1"` 등의 숫자를 새 버전(예: `"1.0.2"`)으로 변경합니다.
2. `versions.json`을 열고 새 버전에 대한 최소 요구 옵시디언 버전 정보를 추가합니다. (예: `"1.0.2": "1.5.0"`)

### ② GitHub 저장소에 코드 업로드 (Push)
수정된 소스 코드(로컬 파일들)를 본인의 GitHub 저장소(`main` 브랜치)에 반영합니다.
```bash
git add .
git commit -m "버전 1.0.2 업데이트: 모달창 디자인 개선"
git push origin main
```

### ③ 새로운 릴리즈(Release) 봇 자동 발급 (업데이트 배포)
이제 옵시디언 앱 사용자들에게 "업데이트가 있습니다"라고 알리기 위해 GitHub 릴리즈를 발급해야 합니다. (수동 파일 업로드가 절대 필요 없는 완전 자동 파이프라인입니다.)

1. 터미널(Git)에서 새로운 버전의 **태그(Tag)를 생성**하고 서버에 올립니다.
   ```bash
   git tag 1.0.27
   git push origin 1.0.27
   ```
2. 위 명령어 실행 직후 깃허브 액션 봇이 수 분 내에 컴파일을 수행하고 결과물(Assets)과 보안 서명을 포함한 릴리즈 페이지를 자동으로 완성해 줍니다.

**✅ 끝입니다!**
릴리즈가 발행되는 즉시 옵시디언 커뮤니티 플러그인 시스템이 이를 감지하고, 기존 플러그인 사용자들의 옵시디언 앱 내에 **[업데이트(Update)]** 버튼을 활성화시켜 줍니다. (심사를 다시 받을 필요 없이 버전업은 즉시 배포됩니다.)
