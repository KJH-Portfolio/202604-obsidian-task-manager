# MyWorld Task Manager - 플러그인 개발 및 공식 등록 가이드북

이 문서는 **MyWorld Task Manager** 플러그인의 로컬 개발 환경 구축 방법부터 로컬 보관소 내 테스트, 그리고 최종적으로 GitHub에 릴리즈하여 옵시디언 커뮤니티 플러그인으로 공식 승인을 받아 배포하는 전체 프로세스를 안내하는 실행 가이드입니다.

---

## 1. 로컬 개발 및 테스트 환경 구축

옵시디언 플러그인은 TypeScript 기반으로 개발되며, 컴파일 과정을 거쳐 하나의 `main.js` 파일로 빌드되어 구동됩니다.

### ① 개발 도구 설치
1.  **Node.js 및 npm 설치**: 개발 컴퓨터에 Node.js가 설치되어 있어야 합니다. (버전 18 이상 권장)
2.  **VS Code 설치**: 코딩과 터미널 제어가 용이한 VS Code 등의 에디터를 준비합니다.

### ② 개발용 뼈대(Boilerplate) 생성 및 패키지 설치
옵시디언 공식 플러그인 템플릿 저장소를 바탕으로 프로젝트 폴더를 구성합니다.
```bash
# 1. 공식 플러그인 샘플 다운로드 및 폴더 생성
npx degit obsidianmd/obsidian-sample-plugin myworld-task-manager

# 2. 프로젝트 폴더로 이동
cd myworld-task-manager

# 3. 개발에 필요한 패키지(obsidian API 등) 자동 설치
npm install
```

### ③ 로컬 테스트 링크 연결 (Symlink 설정)
코드를 수정하고 빌드하면 사용자님의 현재 옵시디언 보관소에서 플러그인이 즉시 새로고침되어 반영되도록 심볼릭 링크(Symlink)를 연결하는 것이 테스트하기 가장 좋습니다.
```powershell
# Windows PowerShell 관리자 권한으로 프로젝트 폴더 내에서 실행
New-Item -ItemType Junction -Path "c:\Users\kim50\OneDrive\Desktop\Obsidian\.obsidian\plugins\myworld-task-manager" -Value "C:\개발폴더경로\myworld-task-manager"
```

### ④ 빌드 실행
개발 폴더 내에서 코드를 작성한 후, 아래 명령어를 실행하여 빌드합니다.
*   **실시간 개발 모드 (추천)**: `npm run dev`
*   **배포용 최종 빌드**: `npm run build`

## 2. 코드 구현 및 로컬 검증 단계 (v1.0.52 최신 기준)

1.  **코드 모듈 작성**: 기획서에 기재된 다수의 모듈(`main.ts`, `settings.ts`, `TaskUtils.ts`, `CalendarWidget.ts` 등) 코드를 `src/` 폴더 내에 작성합니다.
    *   **[최신]**: 설정 탭 구성 시 HTML을 직접 주입하지 않고 옵시디언의 표준 컴포넌트인 `Setting` 클래스를 사용하여 안전하고 통일된 UI를 구축합니다.
2.  **스타일 시트 이식**: 사용자 커스텀 렌더링 스타일 코드를 프로젝트 루트의 `styles.css`에 붙여넣습니다.
3.  **메타데이터 수정**: 루트의 `manifest.json`을 수정하여 고유 ID(`myworld-task-manager`), 버전(`1.0.52`) 등을 기입합니다.
4.  **로컬 보관소 테스트**: 옵시디언 설정 ➔ `커뮤니티 플러그인` ➔ **새로고침**을 통해 테스트합니다. 다중 창(팝아웃) 모드에서도 정상 렌더링되는지 확인합니다.

## 3. GitHub 배포본(Release) 발행

옵시디언 공식 마켓플레이스에 배포하려면, 사용자의 코드가 GitHub에 정상적으로 릴리즈되어 있어야 합니다.

### ① 배포용 Release 자동화 (GitHub Actions & Attestations) ⭐
**[IMPORTANT 변경 사항]**
과거에는 로컬에서 직접 빌드한 후 수동으로 올렸으나, 현재는 깃허브 액션 스크립트(`.github/workflows/release.yml`)가 구축되어 있어 빌드와 **보안 서명(Artifact Attestations)**이 100% 자동화되어 있습니다.

1. 로컬 환경에서 코드 수정 및 버전업(`manifest.json`, `package.json`, `versions.json`)을 마친 후 `Commit & Push` 합니다.
2. 깃허브 터미널(Git) 또는 데스크탑 앱에서 새 버전에 해당하는 **태그(Tag)를 생성하고 Push** 합니다. (예: `git tag 1.0.52` ➔ `git push origin 1.0.52`)
3. **🎉 끝입니다!** 태그가 푸시되는 순간, `.github/workflows/release.yml`에 정의된 액션 워크플로우가 발동하여 클라우드 컨테이너 환경에서 `npm run build`를 수행한 후, 생성된 빌드 산출물(`main.js`, `styles.css`, `manifest.json`)을 자동으로 Release Asset에 업로드하고 배포를 완료합니다.

### ② 수동 배포 방식 (Classic Method)
깃허브 액션을 사용할 수 없거나 직접 업로드가 필요한 경우, 과거의 고전적인 방식으로도 배포가 가능합니다.
1. `manifest.json`과 `versions.json`의 버전을 최신으로 수정합니다.
2. 로컬 터미널에서 `npm run build` 명령을 실행하여 최신 `main.js` 파일을 생성합니다.
3. 깃허브 웹사이트의 저장소 메인 화면 우측 **Releases** ➔ **Draft a new release** 버튼을 클릭합니다.
4. 새로 출시할 **Tag**(예: `1.0.52`)를 생성하고 릴리즈 제목과 노트를 작성합니다.
5. 로컬 프로젝트 폴더에 위치한 3개의 핵심 파일(`main.js`, `manifest.json`, `styles.css`)을 끌어다 놓아 첨부(Attach)합니다.
6. **Publish release** 버튼을 눌러 릴리즈 발행을 수동으로 완료합니다.

## 4. 옵시디언 커뮤니티 플러그인 공식 등록 신청

### ① 공식 개발자 대시보드 로그인 및 연동
1.  **[community.obsidian.md](https://community.obsidian.md)** 에 접속하여 옵시디언 계정으로 로그인합니다.
2.  프로필에서 본인의 **GitHub 계정을 연동(Link)**합니다.

### ② 플러그인 등록 신청 (Submit)
1.  좌측 사이드바의 **Plugins** 메뉴 ➔ **New plugin** 클릭.
2.  본인의 **GitHub Repository URL**을 입력창에 붙여넣고 제출(Submit)을 누릅니다.

### ③ 자동화 검사 및 심사 프로세스
스캔을 통과하면 관리자 수동 코드 리뷰(Manual Review) 대기열로 넘어가며, 최종 승인이 완료되면 전 세계 사용자가 다운로드할 수 있게 됩니다.

## 5. 🚀 향후 업데이트 (버전 업그레이드) 가이드

1. **버전 숫자 올리기**: `manifest.json`, `package.json`의 버전 숫자 및 `versions.json`을 업데이트합니다.
2. **GitHub 저장소에 코드 업로드**: 변경 사항을 `Commit & Push` 합니다.
3. **새로운 태그 Push**: `git tag 1.0.53` ➔ `git push origin 1.0.53` 실행.
4. 액션 봇이 릴리즈를 발급하면, 기존 앱 사용자들에게 **[업데이트(Update)]** 버튼이 즉각적으로 활성화됩니다.
