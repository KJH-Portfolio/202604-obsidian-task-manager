# 옵시디언 플러그인 개발 및 배포 정책 가이드

이 문서는 옵시디언(Obsidian) 커뮤니티 플러그인으로 등록하기 위해 준수해야 하는 최신 개발 정책, 필수 파일 구성, 그리고 배포 프로세스를 정리한 가이드라인입니다.

---

## 1. 핵심 개발 및 보안 정책
옵시디언 팀은 사용자의 데이터 안전과 보안을 최우선으로 생각하므로, 커뮤니티 플러그인 등록 시 엄격한 보안 심사를 진행합니다.

*   **코드 난독화 금지 (Safety & Privacy)**
    *   보안 검토를 위해 모든 소스코드는 난독화(Obfuscation)되지 않은 상태로 제출되어야 합니다.
    *   외부 의존성을 번들링(main.js로 빌드)하되, 사용된 라이브러리와 원본 코드가 명확히 드러나야 합니다.
*   **자체 업데이트 기능 금지**
    *   플러그인이 내부에 자체적으로 코드를 업데이트하거나 다운로드받는 메커니즘을 포함해서는 안 됩니다. 모든 업데이트는 공식 커뮤니티 저장소를 통해 배포되어야 합니다.
*   **개인 정보 및 원격 측정(Telemetry) 제한**
    *   사용자의 동의 없는 텔레메트리, 분석 데이터 전송, 추적 스크립트는 원칙적으로 금지됩니다. 필요하다면 명확한 고지와 사용자 동의 옵션(Opt-in)이 있어야 합니다.
*   **광고 삽입 금지**
    *   플러그인 내부(UI 화면)에 정적/동적 광고를 삽입할 수 없습니다. 후원을 유도하는 링크(Buy me a coffee 등)는 설정 화면에 노출할 수 있습니다.
*   **외부 서비스 이용 시 투명성 제공**
    *   외부 API나 웹 서비스와 통신하는 경우, 사용자가 알 수 있도록 `README.md`에 이를 명시해야 합니다.
*   **동적 코드 실행 금지**
    *   보안 위협 방지를 위해 `eval()` 사용은 금지됩니다.
*   **[최신 업데이트] 투명한 설정 UI 제공**
    *   v1.0.52 버전부터 설정 탭(Settings)의 UI가 옵시디언 공식 표준 컴포넌트로 전면 개편되었습니다.
    *   사용자가 원할 때만 개발 단계 알림을 볼 수 있도록 **토글형 업데이트 공지** 기능이 적용되었습니다.
    *   버그 신고 및 기능 제안을 위한 **공식 피드백 및 지원 링크**가 설정 창에 추가되었습니다.
*   **데이터 보관**
    *   브라우저의 `localStorage` 대신 옵시디언에서 제공하는 공식 API인 `saveData()`와 `loadData()`를 활용해 플러그인 설정을 안전하게 저장합니다.

## 2. 저장소 및 메타데이터 필수 요구사항
플러그인을 배포할 GitHub 저장소의 루트 디렉토리에는 반드시 다음 파일들이 존재해야 합니다.

1.  **`manifest.json`**: 플러그인의 메타데이터를 정의하는 필수 파일
    *   `id`: 다른 플러그인과 중복되지 않는 고유한 ID (`myworld-task-manager` 등)
    *   `name`: 플러그인 표시 이름
    *   `version`: 현재 플러그인 버전 (현재 최신 v1.0.52)
    *   `minAppVersion`: 작동 가능한 최소 옵시디언 버전
    *   `author`: 개발자 이름/닉네임
    *   `description`: 플러그인에 대한 짧은 설명
2.  **`versions.json`**: 버전 이력 관리 파일 (**사실상 필수**)
    *   파일 형식: `{ "1.0.0": "1.5.0", "1.0.1": "1.5.0" }` (key: 플러그인 버전, value: 필요한 최소 옵시디언 버전)
    *   자동화 봇이 스캔 시 이 파일이 있어야 플러그인 업데이트 평가를 제대로 수행합니다.
    *   버전을 올릴 때마다 이 파일에도 새 버전을 반드시 추가해야 합니다. (Release Assets에는 체크하지 않아도 됨, 소스코드에만 유지하면 됨)
3.  **`README.md`**: 플러그인의 작동 방식, 설정 방법, 원격 통신 여부 등을 명시한 문서
4.  **`LICENSE`**: 오픈소스 라이선스 문서 (예: MIT, GPL 등)

### 상표권 정책 (Trademark Policy)
*   플러그인 이름에 **"Obsidian"**을 포함하여 사용자가 이를 옵시디언 공식 기능으로 오해하지 않게 해야 합니다.
    *   *잘못된 예*: `Obsidian Task Sync`
    *   *좋은 예*: `Task Sync for Obsidian` 혹은 `MyWorld Task Manager`

## 3. 빌드 및 배포 프로세스
개발이 완료된 플러그인을 사용자들에게 제공하기 위한 단계입니다.

### 1) 빌드 아티팩트 준비
플러그인을 배포할 때는 GitHub의 **Release** 기능을 사용합니다. 이때 생성하는 릴리즈(Release) 태그의 버전과 `manifest.json`의 `version`이 정확히 일치해야 합니다.
또한 해당 Release의 첨부 파일(Assets)로 반드시 다음 바이너리들이 빌드되어 업로드되어야 합니다.
*   `main.js` (TypeScript/JavaScript 소스코드가 컴파일된 메인 실행 파일)
*   `manifest.json` (메타데이터 파일)
*   `styles.css` (플러그인 고유 CSS 스타일이 있는 경우 필수 첨부)

### 2) 개발자 대시보드를 통한 플러그인 등록
*   과거에는 `obsidianmd/obsidian-releases` 저장소에 직접 Pull Request를 보내 등록했으나, 현재는 **공식 개발자 대시보드(Developer Dashboard)**를 통한 등록으로 개편되었습니다.
*   **제출 방법**:
    1.  [community.obsidian.md](https://community.obsidian.md)에 접속하여 본인의 옵시디언 계정으로 로그인합니다.
    2.  본인의 GitHub 계정을 연동합니다.
    3.  **Plugins** > **New plugin**을 선택하고 본인의 GitHub 저장소 URL을 입력하여 등록 신청을 완료합니다.
*   **자동 검사 봇(Scanner) 작동**:
    *   제출 후 봇이 자동으로 코드를 검사하여 보안 이슈, 가이드라인 위반 사항, 종속성 오류 등을 점검합니다.
    *   자동 검사가 통과되면, 이후 옵시디언 커뮤니티 관리자의 수동 검토를 거쳐 최종적으로 커뮤니티 플러그인 목록에 노출됩니다.
